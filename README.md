스터디는 **파이널 프로젝트 이전인 11월 11일까지** 진행합니다.

## 기본 규칙

- 매주 **공통 문제 1개**를 정해 함께 풉니다.
- 각자 **주마다 최소 3개 문제**를 풉니다.
- 주마다 1회 모임이 있으며 모임 때는 공통 문제와 각자 푼 문제 중 1개에 대한 리뷰를 진행합니다.
- 개인 문제는 아래 팀원별 학습 범위에 맞춰 선택합니다.
- 여유가 있다면 최소 목표에 그치지 않고 추가로 도전합니다.


### 1. 주간 진행 방식

- 한 주는 월요일부터 일요일까지로 정하고, 일요일까지 풀이를 올립니다.
- 주간 최소 3개에는 공통 문제 1개를 포함합니다. 즉, **공통 1개 + 개인 2개 이상**을 기본으로 합니다.
- 다음 주 공통 문제는 팀원들이 번갈아 제안하고, 함께 도전할 수 있는 문제로 정합니다.
- 일정상 목표를 채우기 어렵다면 미리 공유하고, 가능한 분량과 보완 계획을 남깁니다.

### 2. 풀이 제출 방식

- 각자 문제를 풀고 제출할 떄는  `src/<본인 폴더>/<주 단위>/<문제 이름>/`으로 제출합니다. `ex) src/vvipia/week01/pokemon`  
- 또한 해당 디렉터리에는 마크 다운으로 다음 내용을 적어 같이 제출합니다.
  - 문제 이름과 링크
  - 접근 방법과 핵심 아이디어
  - 막혔던 부분이나 새로 배운 점
  - 참고한 자료가 있다면 출처
- 커밋 메시지는 무엇을 풀었는지 알 수 있게 작성합니다. 예: `solve: 폰켓몬 풀이 추가`
- 가능하면 개인 브랜치에서 작업하고 PR로 제출합니다. PR 본문에는 이번에 푼 문제 목록과 질문을 적습니다.
- 다른 팀원의 파일을 수정해야 한다면 먼저 이야기합니다.
- 한 주가 끝나면  `src/<본인 폴더>/<주 단위>/` 에 주간 회고 파일을 생성합니다. 해당 내용은 아래의 4번을 참고 하세요.

### 3. 함께 공부하는 방식

- 공통 문제는 먼저 스스로 고민한 뒤 다른 풀이를 확인합니다.
- 막히면 시도한 방법과 이해되지 않는 부분을 함께 적어 질문합니다.
- 해설이나 AI의 도움을 받았다면 내용을 이해하고 직접 다시 작성합니다. 참고한 부분도 기록합니다.
- 정답 여부뿐 아니라 변수 이름, 가독성, 자료구조 선택, 시간 복잡도도 함께 살펴봅니다.
- 리뷰는 사람을 평가하기보다 코드와 접근 방법에 대한 구체적인 의견으로 남깁니다.
- 매주 다른 팀원의 풀이를 하나 이상 읽고, 배운 점이나 질문을 남기는 것을 권장합니다.

### 4. 주간 회고

주말에 아래 양식으로 한 주를 짧게 정리합니다. 풀지 못한 문제도 시도한 과정과 함께 남깁니다.

```markdown
- 새로 배운 점:
- 막힌 부분 / 함께 이야기하고 싶은 내용:

```

속도와 진도가 달라도 괜찮습니다. 꾸준히 참여하고, 서로 질문하기 편한 스터디를 만들어갑시다.
