- AI 질문 여부: 명함의 긴 쪽을 가로로 몬다는 발상, 완전탐색과의 차이 질문


## 문제 요약

명함의 가로와 세로가 담긴 2차원 배열 `sizes`가 주어집니다.

모든 명함을 넣을 수 있는 지갑의 최소 넓이를 반환합니다.

- 명함은 각각 90도 회전할 수 있습니다.
- 명함끼리 겹쳐도 되며 두께는 고려하지 않습니다.
- 명함 개수는 1 이상 10,000 이하입니다.
- 각 길이는 1 이상 1,000 이하입니다.

| sizes                                  | 반환값 |
|----------------------------------------| --- |
| `[[60,50],[30,70],[60,30],[80,40]]`    | 4000 |
| `[[10,7],[12,3],[8,15],[14,7],[5,15]]` | 120 |
| `[[14,4],[19,6],[6,16],[18,7],[7,11]]` | 133 |

## 접근법

### 1. 명함의 긴 쪽을 가로로 맞추기

각 명함의 두 길이를 비교하여 긴 쪽을 `width`, 짧은 쪽을 `height`에 저장합니다.

```text
[60, 50] → [60, 50]
[30, 70] → [70, 30]
[60, 30] → [60, 30]
[80, 40] → [80, 40]
```

전체 명함에서 가장 긴 길이는 지갑의 어느 한쪽에 반드시 들어가야 합니다.

그쪽을 지갑의 가로로 정하고 모든 명함의 긴 쪽을 맞추면, 세로에는 각 명함의 짧은 쪽만 남습니다. 회전하더라도 각 명함의 짧은 쪽보다 세로를 더 줄일 수는 없으므로 최소 크기를 구할 수 있습니다.

### 2. 가로와 세로의 최댓값 구하기

모든 명함이 들어가려면 지갑의 가로와 세로는 각각 다음 길이 이상이어야 합니다.

- `maxWidth`: 명함별 긴 쪽의 최댓값
- `maxHeight`: 명함별 짧은 쪽의 최댓값

첫 예제에서는 `maxWidth = 80`, `maxHeight = 50`입니다.

### 3. 넓이 반환하기

모든 명함을 확인한 뒤 두 값을 곱합니다.

```java
answer = maxWidth * maxHeight;
```

## Java 코드

직접 작성한 코드에서 넓이 계산만 반복문 밖으로 옮겼습니다.

```java
public class S3 {
    public int solution(int[][] sizes) {
        int answer = 0;

        int width;
        int height;

        int maxWidth = 0;
        int maxHeight = 0;

        for (int i = 0; i < sizes.length; i++) {
            if (sizes[i][0] >= sizes[i][1]) {
                width = sizes[i][0];
                height = sizes[i][1];
            } else {
                width = sizes[i][1];
                height = sizes[i][0];
            }

            if (width > maxWidth) {
                maxWidth = width;
            }

            if (height > maxHeight) {
                maxHeight = height;
            }
        }

        answer = maxWidth * maxHeight;

        return answer;
    }
}
```

프로그래머스에 제출할 때는 `public class S3`를 `class Solution`으로 변경합니다.

## 시간 복잡도

- 시간 복잡도: **O(n)**  
  명함이 n개일 때 각 명함을 한 번씩 확인합니다.
- 공간 복잡도: **O(1)**  
  명함 개수와 관계없이 일정한 개수의 변수만 추가로 사용합니다.

## 시행착오 및 배운 점

### 1. 문제에서 허용하는 배치 이해하기

처음에는 명함끼리 겹쳐도 되는지 확인했습니다.

명함을 나란히 배치하는 문제가 아니라, 포개어 넣었을 때 각 명함이 지갑 안에 들어가면 되는 문제였습니다.

### 2. 2차원 배열의 위치 구분하기

처음에는 다음처럼 접근하려고 했습니다.

```java
sizes[i][i]
sizes[i][i + 1]
```

하지만 앞의 `i`는 명함 번호이고, 뒤의 위치는 해당 명함의 두 길이를 나타냅니다.

```java
sizes[i][0] // 현재 명함의 첫 번째 길이
sizes[i][1] // 현재 명함의 두 번째 길이
```

각 명함에는 두 값만 있으므로 뒤의 위치에는 `0`, `1`을 사용해야 합니다.

### 3. 대입 방향 이해하기

최댓값을 갱신할 때 처음에는 다음과 같이 생각했습니다.

```java
width = maxWidth;
```

하지만 바꾸려는 값은 지갑의 가로인 `maxWidth`이므로 방향이 반대였습니다.

```java
maxWidth = width;
```

Java의 `=`는 오른쪽 값을 왼쪽 변수에 저장합니다.
