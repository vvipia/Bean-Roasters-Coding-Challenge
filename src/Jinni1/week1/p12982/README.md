# 예산

## 1. 문제 정보

- 플랫폼: 프로그래머스
- 난이도: Level 1
- 문제 링크: [예산](https://school.programmers.co.kr/learn/courses/30/lessons/12982)
- 사용 언어: Java
- 풀이 코드: [P12982.java](./P12982.java)

## 2. 문제 설명

부서별 신청 금액 배열 `d`와 전체 예산 `budget`이 주어졌을 때, 지원할 수 있는 최대 부서 수를 구합니다. 각 부서를 지원하려면 신청 금액 전액을 지급해야 하며, 일부 금액만 지원할 수는 없습니다.

## 3. 접근 방법

같은 수의 부서를 지원한다면, 신청 금액이 작은 부서부터 선택할 때 총비용이 가장 작습니다. 따라서 신청 금액을 오름차순으로 정렬하고, 예산 안에서 작은 금액부터 선택하는 그리디 전략을 사용했습니다.

1. `Arrays.sort(d)`로 신청 금액을 오름차순으로 정렬합니다.
2. 배열을 순회하며 `sum + d[i]`가 예산을 초과하는지 먼저 확인합니다.
3. 예산 이내이면 신청 금액을 `sum`에 누적하고, 지원한 부서 수 `n`을 갱신합니다.
4. 예산을 초과하면 반복을 종료하고 지원한 부서 수를 반환합니다.

정렬된 배열에서 현재 금액을 추가할 수 없다면, 이후 금액은 모두 같거나 더 크므로 추가할 수 없습니다. 따라서 남은 부서를 확인하지 않고 종료해도 됩니다.

### 예시

신청 금액이 `[1, 3, 2, 5, 4]`, 예산이 `9`일 때 정렬 결과는 `[1, 2, 3, 4, 5]`입니다.
1, 2, 3을 신청한 부서를 지원하면 총금액은 6이고, 다음 금액 4를 더하면 예산 9를 초과합니다. 따라서 반환값은 `3`입니다.

## 4. 핵심 개념

### 그리디 선택이 최적인 이유

어떤 k개 부서를 선택하더라도 그 신청 금액의 합은 가장 작은 k개 금액의 합보다 작을 수 없습니다. 선택한 부서 중 더 비싼 부서를 선택하지 않은 더 저렴한 부서로 바꾸면, 지원 부서 수는 유지하면서 비용을 줄이거나 같게 만들 수 있기 때문입니다.

따라서 가장 작은 k개 금액의 합이 예산을 초과한다면, 다른 조합으로도 k개 부서를 지원할 수 없습니다. 작은 금액부터 선택하다가 예산을 초과하기 직전에 멈추면 최대 지원 부서 수를 구할 수 있습니다.

### Arrays.sort()

`Arrays.sort(d)`는 별도의 정렬된 배열을 반환하지 않고, 전달받은 배열 자체의 순서를 변경합니다. 이 풀이에서는 원래 부서의 순서가 필요하지 않으므로 입력 배열을 그대로 정렬했습니다.

### 예산과 합계가 같은 경우

신청 금액을 추가한 합계가 예산과 같으면 지원할 수 있습니다. 따라서 종료 조건은 `sum + d[i] >= budget`이 아니라 `sum + d[i] > budget`입니다.

## 5. 시간·공간 복잡도

`N`은 신청 금액 배열 `d`의 길이입니다.

- **시간 복잡도: O(N log N)** — 배열 정렬에 O(N log N), 정렬 이후 순회에 최대 O(N)이 걸리므로 전체 시간 복잡도는 O(N log N)입니다.
- **직접 사용하는 추가 공간: O(1)** — 정렬 내부 공간을 제외하면 `sum`, `n`, `i` 등 고정된 개수의 변수만 사용합니다.
