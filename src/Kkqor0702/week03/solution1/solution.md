# 문제 이름: 겹치는 선분의 길이

**출처:** 프로그래머스  
**난이도:** Lv.0  
**유형:** 배열, 구현, 해시맵, 구간 탐색  
**소요 시간:** ?  
**AI 질문:** O (풀이 과정에서 힌트 및 구현 관련 질문)

## 1. 문제 요약

세 개의 선분이 주어졌을 때, 두 개 이상의 선분이 겹치는 부분의 총길이를 반환하는 문제.

각 선분은 `[start, end]` 형태로 주어지며, 좌표의 범위는 -100 이상 100 이하이다.

- 입력: `lines = [[0, 2], [-3, -1], [-2, 1]]`
- 출력: `2`
- 겹치는 구간: `[-2, -1]`, `[0, 1]`

## 2. 나의 문제 접근법

1. 각 선분을 길이가 1인 구간들로 나누어 생각한다.
2. `HashMap<Integer, Integer>`을 사용하여 각 구간의 시작 좌표를 Key, 해당 구간을 포함하는 선분의 개수를 Value로 저장한다.
3. 향상된 for문으로 `lines`의 각 선분을 순회한다.
4. 각 선분의 시작 좌표부터 끝 좌표 직전까지 반복하면서, `getOrDefault()`를 사용해 해당 구간의 등장 횟수를 1씩 증가시킨다.
5. `map.values()`로 모든 Value를 순회한다.
6. Value가 2 이상인 구간마다 `answer`를 1씩 증가시킨다.
7. 최종적으로 두 개 이상의 선분이 겹치는 구간의 총길이를 반환한다.

## 3. 시간 복잡도

- 각 선분의 길이만큼 반복하며 Map에 등장 횟수 저장: O (N × L)
- `map.values()`로 모든 구간의 등장 횟수 확인: O (K)

**최종 시간 복잡도: O (N × L + K)**  
**공간 복잡도: O (K)**

※ N은 선분의 개수, L은 선분의 최대 길이, K는 Map에 저장된 서로 다른 단위 구간의 개수이다.

※ 이 문제에서는 선분이 3개이고 좌표 범위가 -100부터 100까지로 고정되어 있으므로, 제한사항을 상수로 취급하면 시간 및 공간 복잡도는 O (1)이다.

## 4. 시행착오 및 배운 점

- 처음에는 `Map`을 사용해 해결하려고 했지만 구현 과정에서 막혔었다.
- 처음 작성한 코드에서는 `line[0]`을 Key로 사용하여 각 선분의 시작 좌표에만 등장 횟수가 누적되는 문제가 있었다.
- 반복문의 변수 `i`를 Key로 사용하도록 수정하여 길이가 1인 각 구간의 등장 횟수를 계산할 수 있었다.
- 선분 전체의 겹침 여부가 아니라, 길이가 1인 구간을 기준으로 겹치는 횟수를 계산하면 총길이를 구할 수 있다는 점을 배웠다.
- `getOrDefault()`를 활용하면 Map에 Key가 존재하지 않는 경우에도 기본값을 사용하여 등장 횟수를 누적할 수 있다.
- `map.values()`를 사용하면 Map에 저장된 모든 Value를 순회할 수 있다는 점을 알게 되었다.
- `Map.Entry<K, V>`는 Key-Value 한 쌍을 나타내는 인터페이스이다.
    - `getKey()`와 `getValue()`로 각각의 값에 접근할 수 있다.
- `map.entrySet()`은 Map에 저장된 모든 Key-Value 쌍을 `Set<Map.Entry<K, V>>` 형태로 반환한다.
    - 반환된 Set의 원소 타입이 `Map.Entry<K, V>`이므로 Entry 단위로 순회할 수 있다.
- 이번 문제처럼 Value만 확인하면 되는 경우에는 `entrySet()`보다 `values()`를 사용하는 것이 더 간단하다.
