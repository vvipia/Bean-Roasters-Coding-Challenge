문제 이름: 최댓값 만들기 (1)

**출처:** [프로그래머스](https://school.programmers.co.kr/learn/courses/30/lessons/120847)  
**난이도:** Lv.0  
**유형:** 배열, 완전탐색, 이중 반복문  
**소요 시간:** 미기록  
**AI 질문:** O (완전탐색 구현)

## 1. 문제 요약

정수 배열 `numbers`에서 서로 다른 위치의 원소 두 개를 골라 곱했을 때, 가장 큰 값을 반환한다.

- 원소의 범위: 0 이상 10,000 이하
- 배열 길이: 2 이상 100 이하
- 값이 같아도 위치가 다르면 함께 선택할 수 있다.

| 입력                              | 출력  |
|-----------------------------------|-------|
| `[1, 2, 3, 4, 5]`                 | `20`  |
| `[0, 31, 24, 10, 1, 9]`           | `744` |
| `[2, 2, 3]` (학습 중 확인한 예시) | `6`   |

## 2. 나의 문제 접근 법

처음에는 배열을 한 번 돌면서 가장 큰 값 두 개를 찾는 방식으로 풀었다. 이후 모든 두 원소의 조합을 직접 확인하는 **완전탐색** 방식으로 다시 풀었다.

### 완전탐색 풀이

1. 지금까지 확인한 곱의 최댓값을 저장할 `max`를 0으로 시작한다.
2. 바깥 반복문의 `i`로 첫 번째 원소의 위치를 선택한다.
3. 안쪽 반복문의 `j`는 `i + 1`부터 시작하여 두 번째 원소를 선택한다.
4. `numbers[i] * numbers[j]`가 `max`보다 크면 `max`를 바꾼다.
5. 모든 조합을 확인한 뒤 `max`를 반환한다.


원소가 모두 0 이상이므로 곱도 0 이상이다. 따라서 `max`를 0으로 시작해도 된다.

### `j = i + 1`인 이유

`j`를 `i`의 다음 위치부터 움직이면 같은 위치를 두 번 선택하지 않고, 순서만 바뀐 조합도 다시 확인하지 않는다.

`numbers = [2, 2, 3]`이면 다음 세 조합을 확인한다.

| i | j | 실제 계산 |
| --- | --- | --- |
| 0 | 1 | `2 * 2 = 4` |
| 0 | 2 | `2 * 3 = 6` |
| 1 | 2 | `2 * 3 = 6` |

`i = 2`일 때는 `j = 3`으로 시작하지만, 배열 길이가 3이므로 안쪽 반복문이 실행되지 않는다.
최종 결과는 `6`이다. `3`이 있는 위치를 두 번 고를 수 없으므로 `9`는 나오지 않는다.

### 처음 작성한 풀이와 비교

| 풀이 | 방법 | 시간 복잡도 | 추가 공간 |
| --- | --- | --- | --- |
| 최댓값 두 개 찾기 | 한 번 순회하며 가장 큰 값과 두 번째로 큰 값을 유지 | O(N) | O(1) |
| 완전탐색 | 서로 다른 두 위치의 모든 조합을 확인 | O(N²) | O(1) |

이 문제는 음수가 없으므로 가장 큰 값 두 개의 곱이 정답이다. 처음 풀이가 더 빠르고,
이번 풀이는 모든 조합을 빠짐없이 확인하는 연습에 도움이 되었다.
최댓값 두 개를 찾을 때도 같은 값이 서로 다른 위치에 있다면 두 개 모두 후보가 될 수 있다.


## 3. 시간 복잡도

배열 길이를 `N`이라고 하면 확인하는 조합 수는 다음과 같다.

```text
(N - 1) + (N - 2) + ... + 1 = N × (N - 1) / 2
```

- **시간 복잡도: O(N²)** — 배열이 커질수록 확인할 조합 수가 대략 N의 제곱에 비례한다.
- **공간 복잡도: O(1)** — 입력 배열 외에 `max`, `i`, `j`만 사용하므로 추가 공간은 일정하다.

배열 길이가 최대 100이므로 최대 4,950개의 조합을 확인한다.

## 4. 시행착오 및 배운 점

### 인덱스와 실제 값을 혼동했다

처음에는 `i * j`로 계산했다. 하지만 `i`, `j`는 배열의 위치를 나타내는 번호인 **인덱스**다. 실제 값을 곱하려면 `numbers[i] * numbers[j]`로 작성해야 한다.

예를 들어 `[3, 5, 7, 9]`에서 `i = 0`, `j = 1`이면 다음과 같다.

- `i * j`: 위치 번호끼리 곱하므로 `0 * 1 = 0`
- `numbers[i] * numbers[j]`: 배열의 값끼리 곱하므로 `3 * 5 = 15`

### 안쪽 반복문을 항상 1부터 시작했다

말로는 `i + 1`부터 시작해야 한다고 설명했지만, 처음 코드에는 `j = 1`로 작성했다. 이렇게 하면 `i = 1`, `j = 1`처럼 같은 위치를 선택하거나, `(1, 2)`와 `(2, 1)`처럼 같은 조합을 다시 확인할 수 있다.

`j = i + 1`로 수정하여 **현재 위치의 뒤쪽 원소만 선택**하도록 했다.

### 값이 같은 것과 위치가 같은 것은 다르다

`[2, 2, 3]`의 두 `2`는 서로 다른 위치에 있으므로 함께 선택할 수 있다. 이 예시의 정답을 `6`이라고 답하며, 같은 원소를 두 번 쓰는 것과 같은 값을 가진 두 원소를 쓰는 것의 차이를 확인했다.
