# 문제 이름: 가장 큰 수

**출처:** 프로그래머스  
**난이도:** Lv.2  
**유형:** 정렬, 문자열, Comparator  
**소요 시간:** ?  
**AI 질문:** O

## 1. 문제 요약

0 또는 양의 정수가 담긴 배열 numbers의 순서를 재배치하여 만들 수 있는 가장 큰 수를 문자열로 반환한다.

- 입력: `[6, 10, 2]`
- 출력: `"6210"`
- 입력: `[3, 30, 34, 5, 9]`
- 출력: `"9534330"`
- 주요 조건:
    - 배열 길이는 1 이상 100,000 이하이다.
    - 각 원소는 0 이상 1,000 이하이다.
    - 결과가 매우 클 수 있으므로 문자열로 반환한다.
    - 모든 원소가 0이면 "0"을 반환해야 한다.

## 2. 나의 문제 접근법

1. 처음에는 숫자의 자릿수에 따라 값을 보정하는 res () 함수를 만들어 정렬 기준으로 사용하려고 하였다.
2. 구현 중 AI에 질문하여, 두 숫자를 양쪽 순서로 이어 붙인 결과를 비교하는 기준을 학습하였다.
3. Arrays.stream (numbers).boxed ()로 int 값을 Integer로 변환한다.
4. sorted ()에 직접 작성한 Comparator를 전달한다.
5. 두 숫자 a와 b로 문자열 ab와 ba를 만든다.
6. ba.compareTo (ab)를 반환하여 더 큰 문자열을 만드는 순서로 정렬한다.
7. mapToInt (Integer::intValue).toArray ()로 정렬 결과를 int 배열로 변환한다.
8. 정렬된 숫자를 순서대로 문자열에 이어 붙여 반환한다.

※ 제출한 코드 기준으로 작성하였다.
※ 모든 값이 0인 경우의 처리와 StringBuilder 사용은 코드 리뷰에서 제안받은 개선 사항이다.

## 3. 시간 복잡도

- Stream 변환 및 배열 생성: O (N)
- 정렬: O (N log N)
    - 각 숫자는 최대 4자리이므로 비교 문자열의 길이는 상수 범위이다.
- 반복문에서 문자열을 +=로 누적: 최악 O (N²)
    - 반복할 때마다 기존 문자열을 복사하는 비용이 발생한다.

**최종 시간 복잡도: 최악 O (N²)**  
**공간 복잡도: O (N)**

※ N = numbers의 길이
※ 공간 복잡도는 정렬과 변환에 필요한 배열 및 결과 문자열 등
동시에 필요한 공간을 기준으로 한다.
※ StringBuilder로 누적하면 전체 시간 복잡도를 O (N log N)으로 개선할 수 있다.

## 4. 시행착오 및 배운 점

- 처음에는 각 숫자에 독립적인 우선순위 값을 부여하려 했지만 정렬 기준을 구현하는 데 어려움을 겪었다.
- 두 숫자를 이어 붙인 ab와 ba를 비교하면 어느 숫자를 앞에 배치해야 하는지 판단할 수 있음을 배웠다.
    - 3과 34: "334"보다 "343"이 크므로 34가 먼저 온다.
    - 3과 30: "303"보다 "330"이 크므로 3이 먼저 온다.
- Comparator는 한 번에 두 원소를 비교하고, 정렬 기능은 이 비교를 반복하여 전체 순서를 결정한다.
- 문자열 길이가 같고 숫자로만 이루어져 있다면 compareTo ()의 사전식 비교 결과를 숫자의 대소 비교에 사용할 수 있다.
- 큰 조합을 먼저 배치하기 위해 ab.compareTo (ba)가 아닌 ba.compareTo (ab)를 사용하였다.
- 중괄호를 사용하는 람다에서 값을 반환하려면 return이 필요하고, Comparator의 비교 결과는 int여야 한다.
- int[]에는 Arrays.sort ()의 Comparator를 직접 전달할 수 없다.
- boxed ()로 Integer 스트림을 만들면 sorted ()에 Comparator를 전달할 수 있다.
- Arrays.sort ()는 배열, Collections.sort ()는 List, Stream.sorted ()는 Stream을 정렬한다.
- Collectors는 Stream의 결과를 List 등으로 모을 때 사용한다.
- Comparator.comparing ()은 각 원소에서 비교할 기준값을 추출할 때 적합하다.
- 이 문제처럼 두 원소를 함께 사용해 비교값을 만드는 경우에는 두 인자 람다로 직접 비교하는 방식이 적합하다.
- 코드 리뷰에서 모든 원소가 0이면 "000"이 아닌 "0"을 반환하도록 별도 처리가 필요함을 확인하였다.
- 문자열을 반복해서 +=로 연결하는 대신 StringBuilder.append ()를 사용하면 누적 복사 비용을 줄일 수 있음을 배웠다.
